Design: content identity is workspace-local, with exact-byte fingerprints shared only through permission-filtered records; linking never changes source grants. Capture events retain original bytes and source URL independently of content version. Schema drafts are immutable snapshots and do not change published processing. The bounded typed connector uses explicit exact labels followed by a colon, typed/unit/enum validation and segment-backed candidate retention; unsupported natural-language inference remains unknown. It makes no provider/model calls and claims no AI inference. Explicit draft previews are marked preview. Publication is a later Batch 4 story. Type corrections queue current-version jobs; missing published schemas yield action-required instead of pretending extraction completed.

Migration 0005 is additive except converting the capture-to-record one-to-one relation into a many-to-one foreign key so repeated capture events can share stable records. Existing rows remain valid; legacy records without canonical URLs/revisions remain visible with an explicit evidence-unavailable notice. No destructive backfill or live migration is performed. Rollback after new writes requires preserving/restoring new revision tables rather than dropping them and claiming lossless rollback.

Exports retain the existing JSON endpoint contract, add explicit preview/field selection and CSV, bound exports to 100 records, recheck source export grants and exclude quarantined originals. Originals are authorised download references, not unbounded inline blobs. CSV values are protected against spreadsheet formula execution. Query counts/results share one permission/filter path, with stable sort and preserved return query/page anchors.

Native APLYD adoption/QA bindings remain draft. Implementation, engineering checks, separate-agent review, merge, native product acceptance and production deployment remain separate. No new credentials, paid services or live deployment are authorised.

Classification is conservative: this connector recognises explicit source `Type:` labels whose keys are published. Bare/unstructured mentions do not establish type; ambiguous/unmatched content stays Unknown and discoverable. Multiple explicit keys can be assigned. Human corrections are versioned, actor/reason audited and source-permission checked.
